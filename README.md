# Yii2 Order List Management System (Highload Optimized)

Тестовое задание по реализации модуля управления и фильтрации заказов на базе фреймворка Yii2 (Basic), развернутого в Docker-окружении с СУБД MySQL 8.0.

## 🚀 Архитектурные особенности и оптимизация (Highload)

Приложение спроектировано с расчетом на работу с большими объемами данных (100 000+ записей) и жестким ограничением по оперативной памяти (`memory_limit = 128M`).

* **Глобальный слой моделей и репозиториев (Enterprise-подход):** Базовая доменная модель `Order` вынесена в глобальное пространство `app\models`, а логика SQL-запросов и Highload-оптимизаций инкапсулирована в выделенном каталоге `app\models\query\OrderQuery`. Модуль `orders` полностью разгружен и отвечает исключительно за UI-слой, что позволяет переиспользовать доменную логику в консольных командах или API.
* **Соблюдение принципа DRY:** Вся дублирующаяся логика сквозного и текстового поиска изолирована внутри приватного метода `applySearchFilter()` класса `OrderQuery`.
* **Оптимизация индексов СУБД (MySQL 8.0):**
    * Добавлен трехкомпонентный составной индекс `['status', 'mode', 'service_id']` и дополняющий его `['status', 'service_id']`. Это позволило перевести тяжелые агрегирующие запросы подсчета динамических каунтеров в режим `Using index`, снизив время выполнения с ~65 ms до **0.6 ms**.
    * Поиск по имени пользователя `Username` оптимизирован за счет комбинации составного индекса `['status', 'user_id']` и изоляции релейшн-поиска: `OrderSearch` выполняет текстовый поиск по таблице `users` **строго один раз**, кэширует массив ID и скармливает его подзапросам в виде `WHERE IN (...)`. Это снизило время выполнения с 23.3 ms до **1.3 ms** и устранило дублирование запросов (N+1).
    * Для сквозного поиска по ссылкам (`Link`) медленный оператор `LIKE '%...%'` заменен на полноценный **`FULLTEXT` индекс** с использованием `MATCH(...) AGAINST(...)`, что снизило время выполнения с 33.2 ms до **6.2 ms**.
* **Потоковый экспорт CSV без утечек памяти:** Выгрузка результатов (*Save result*) оптимизирована: используется пакетная курсорная выборка `each(500)` в сочетании с методом `asArray()`. Данные стримятся напрямую в выходной поток через `Response::sendStreamAsFile()`, благодаря чему потребление RAM удерживается в пределах **15–20 МБ** независимо от объема выборки.
* **Мультиязычность (i18n):** Все интерфейсные элементы, табы, выпадающие списки и предлоги пагинации обернуты в компонент `i18n` модуля. Локализация приложения переключается глобально одной строкой через конфигурацию окружения `.env`.

## ⚠️ Рекомендации по Production-деплою (Zero-Downtime DDL)

На продакшене с миллионными логами выполнение миграции с добавлением тяжелого `FULLTEXT` индекса через стандартный `ALTER TABLE` заблокирует таблицу `orders` на запись (`Table Lock`), что приведет к `502 Bad Gateway`.

Для безопасного применения структуры на проде рекомендуется использовать утилиту **`pt-online-schema-change`** от Percona:
1. Инструмент создает теневую копию таблицы.
2. Постепенно переливает данные чанками, не блокируя операции чтения и записи основного приложения.
3. Мгновенно подменяет таблицы местами через атомарный `RENAME TABLE`.

## 📂 Структура проекта

* `docker/` — Инфраструктурный слой проекта (`docker-compose.yml`, `.env`, хосты Nginx). Корень репозитория полностью очищен от конфигураций контейнеров.
* `migrations/` — Вынесенный в корень репозитория изолированный каталог миграций СУБД, работающий под собственным пространством имен `namespace migrations;`.
* `app/` — Исходный код приложения Yii2.
* `app/models/` — Глобальный доменный слой моделей (`Order`, `User`, `Service`).
* `app/models/query/` — Глобальный слой кастомных ActiveQuery запросов (`OrderQuery`).
* `app/modules/orders/` — Автономный изолированный веб-модуль управления заказами.


## 🛠️ Инструкция по развертыванию

1. **Клонируйте репозиторий и перейдите в корень проекта:**
   ```bash
   git clone https://github.com/ponteleev/yii2_order_list_filtered/
   cd yii2_order_list_filtered
   ```

2. **Создайте локальный файл конфигурации окружения внутри папки инфраструктуры:**
   ```bash
   cp docker/.env_dist docker/.env
   ```
   *(Параметры портов, доменов и языков настраиваются гибко. По умолчанию задан `APP_LANGUAGE=en-US`).*

3. **Перейдите в папку Docker и запустите оркестратор контейнеров:**
   ```bash
   cd docker
   docker compose up -d
   ```

4. **Установите зависимости Composer и обновите кэш автозагрузчика (PSR-4):**
   ```bash
   docker compose exec php composer install
   docker compose exec php composer dump-autoload
   ```

5. **При необходимости положите ваш файл с дампом данных `db_data.sql` по пути:**
   `/migrations/db_data.sql`

6. **Запустите миграции для автоматического развертывания структуры СУБД, Highload-индексов и сидирования данных:**
   ```bash
   docker compose exec php php yii migrate/fresh --interactive=0
   ```

После выполнения команд веб-интерфейс системы со всеми оптимизированными фильтрами будет доступен по ЧПУ-адресу: **`http://localhost:8080/orders`**.
